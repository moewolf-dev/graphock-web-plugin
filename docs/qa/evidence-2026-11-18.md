E2E notes:

- Branded Chrome 157 ignores `--load-extension`; the script uses a Playwright-managed
  **Chrome for Testing** binary and falls back to `CHROME_PATH`.
- The E2E build (`dist/e2e`) adds `<all_urls>` **only for the test**, because `activeTab` is
  granted by a real toolbar click, which Playwright cannot perform. The shipped build
  (`dist/chrome`) keeps zero host permissions and is what the packaging script reads.

## Self-audit (second pass)

- Cross-origin image access is optional at install time; images are fetched by the background
  worker only after the user grants the optional permission.
- Shadow DOM (open roots) and iframe placeholders are captured; CSS background images and webfonts
  are inlined with size caps.
- Capture times out after 20 s; the popup can cancel and ignores stale responses.
- Local “Save .zip” packages the document, manifest and assets deterministically.
- History (metadata only), diagnostics, settings export/import and clear-all are in options.
- UI labels follow the browser language (en / zh-CN); protocol errors stay English by design.
- Context menu and keyboard shortcuts clip without opening the popup.

## Known gaps at this snapshot

- Real toolbar capture (activeTab) and the OS protocol dialog are still manual checks.
- Safari container build succeeds, but running it in Safari is still manual (see `safari-2026-11-18.md`).
- Readable extraction now uses Readability; Defuddle comparison (V-04) is still pending.
- CSS background images and webfonts are not inlined; cross-origin stylesheets are skipped (CORS).
- Local saves are single files; embedded images are only carried in the handoff package.
- Downloads go through an offscreen document + Blob URL because Chrome interrupts `data:` URL
  downloads from MV3 service workers. This adds the `offscreen` permission (snapshot updated).
