# Packaged App system E2E — 2026-11-20

This is the manual gate between "CI green" and "Chrome tag / App merge". No step
here can run in remote CI: the OS protocol prompt and the App confirmation are
native UI.

Generate fresh samples (new `clipId` and temp file) with:

```bash
cd graphock-web-plugin
pnpm qa:samples
```

The generator validates the protocol URL length and writes:

- `inline.url` — channel A
- `file.url` — channel B, payload in `$TMPDIR/graphock-system-e2e/`
- `wake-direct.url` / `wake-mas.url` — channel C
- `handoff.json`, `manifest.json`, `README.txt`

Both generated URLs were parsed with the App receiver before this checklist was
written: inline `channel=inline`, file `channel=file`, asset inlines only at the
image reference, and the code fence/prose keep `assets/pixel.png`.

## A. Direct build — required

Launch the Direct build once (registers `graphock-direct`):

```bash
open "tmp/unsigned-mac/direct-0.0.12-arm64/mac-arm64/Graphock Direct.app"
```

Load the unpacked Chrome build:

1. `chrome://extensions` → Developer mode → Load unpacked →
   `graphock-web-plugin/apps/extension/dist/chrome`.
2. Open a normal article, capture it, choose **Open in Graphock**.

Expected: OS protocol prompt → App confirmation (title/source/format/size) →
file appears in the workspace file list.

Then test the generated links directly:

```bash
open "$(cat artifacts/system-e2e/inline.url)"
open "$(cat artifacts/system-e2e/file.url)"
open "$(cat artifacts/system-e2e/wake-direct.url)"
```

- [ ] Inline import succeeds.
- [ ] File-channel import succeeds (payload is under `TMPDIR`).
- [ ] Wake link opens the file picker; selecting `handoff.json` imports it.
- [ ] The imported document inlines the 1×1 PNG as `data:image/png;base64,`.
- [ ] The code fence and prose still contain `assets/pixel.png`.
- [ ] Running the same inline URL again returns `E_DUPLICATE_CLIP` and does not
      create a second workspace entry.
- [ ] No console error in the extension service worker or App log contains the
      payload/URL.

## B. MAS sandbox build

Launch `tmp/sandbox-mac/Graphock.app` (scheme `graphock`).

- [ ] `open "$(cat artifacts/system-e2e/wake-mas.url)"` opens the picker and
      importing the selected `handoff.json` succeeds.
- [ ] Inline `graphock://import#p=…` succeeds. Generate a MAS-scheme inline URL
      by replacing the scheme in `inline.url` (payload is scheme-independent).
- [ ] File channel (`?file=…`) is rejected with `E_PATH_NOT_ALLOWED`; nothing is
      written to the workspace.
- [ ] Picker cancellation shows no error dialog.

## C. Windows cold start / second instance

On a Windows machine with the Direct build:

- [ ] App not running + open an import URL → cold start imports.
- [ ] App running + open an import URL → `second-instance` imports once.
- [ ] Login callback still routes to auth, never to the importer.
