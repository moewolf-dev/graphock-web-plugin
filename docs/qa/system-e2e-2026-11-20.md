## Automated lane

```bash
cd graphock-web-plugin
pnpm qa:system
```

`qa:system` performs:

1. Fresh samples with **one clipId per success path** (`inline`, `file`,
   `inline-mas`, `file-mas`, `wake-package`); only `inline-duplicate.url` reuses
   the inline id.
2. Extension build with E2E host permission.
3. Chromium captures an incompressible page, clicks **Open in Graphock** with the
   MAS scheme, and downloads the real `.graphock-clip.json`.
4. The App build runs its Electron protocol lane with that **exact downloaded
   file**:
   - inline import writes/mounts/records and the Files page shows the file;
   - the image is inlined and prose/code fences are untouched;
   - duplicate returns `E_DUPLICATE_CLIP` with no second entry;
   - cancel writes nothing;
   - MAS rejects `?file=` with `E_PATH_NOT_ALLOWED` but imports inline;
   - wake picker imports a selected file;
   - the browser-downloaded package imports through the wake picker.

`--skip-build` reuses an existing App `out/`; the default also runs
`pnpm build` in the App repository. Both repos get isolated temp `userData`;
the duplicate assertion deliberately runs in the same temp directory after the
first inline import.

## Manual smoke 1 — Chrome toolbar → Direct App

This is the only check that can prove the browser's own `activeTab` grant and
protocol prompt; scripted dispatch cannot.

1. Launch the Direct build once:
   `open "tmp/unsigned-mac/direct-0.0.12-arm64/mac-arm64/Graphock Direct.app"`.
2. Load `apps/extension/dist/chrome` as an unpacked extension.
3. Open a normal article and click the toolbar icon (not a context menu).
4. Confirm the browser does not show a permission error, capture completes.
5. Click **Open in Graphock**; approve the browser protocol prompt.
6. Confirm the App's native confirm dialog shows title/source/format/size, then
   accept.

Pass: the file appears in the workspace and opens with images intact.

- [ ] Toolbar click grants `activeTab` and captures.
- [ ] Browser protocol prompt appears and routes to the Direct App.
- [ ] App confirmation appears and the file is visible.
- [ ] No payload or import URL appears in either log.

## Manual smoke 2 — MAS sandbox + real downloaded package

Use the package produced by the automated lane:

`artifacts/system-e2e/downloaded-wake-package.graphock-clip.json`

If `qa:system` has not run, run it first; do not substitute a hand-made JSON.

1. Launch `tmp/sandbox-mac/Graphock.app`.
2. Open `graphock://import` (or click **Open in Graphock** with the MAS target).
3. In the App picker, select `downloaded-wake-package.graphock-clip.json`.
4. Accept the confirmation.

Pass: the sandbox opens the security-scoped file, imports it, and the document
appears with the captured text. No copy of the package is left unreadable after
the import.

- [ ] `graphock://import` activates the MAS App.
- [ ] The real browser download is selectable and readable.
- [ ] Import succeeds after the picker closes (bookmark scope held).
- [ ] `graphock://import?file=…` is rejected and writes nothing.

## Windows

Prefer the automated lane on a Windows runner with the scheme registered
(`Start-Process <url>` for cold start, then a second call for the existing
instance). If the runner is not available, keep one manual pass:

- [ ] App closed + URL → cold start imports once.
- [ ] App open + URL → `second-instance` imports once.
- [ ] Login callback still routes to auth.
